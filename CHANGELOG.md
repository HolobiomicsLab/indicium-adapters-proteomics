## [0.2.1] — 2026-08-22

Adversarial review against the mzTab 1.0 specification, the PSI-MS controlled
vocabulary and the `indicium-adapters-metabolomics` sibling.

### Fixed
- **The `modifications` column was split on bare commas**, but mzTab §5.8 lets a
  modification object embed a cvParam of its own — a neutral loss, or a
  per-site probability — and those carry commas. The fragments were then read as
  further modifications, so a file that follows the spec's own PSM example
  (`10[MS,MS:1001876, modification probability, 0.8]-MOD:00412`) lost its real
  modification and gained a fabricated `carries_modification MS:1001876`; a
  reported neutral loss produced a fabricated `carries_modification MS:1001524`.
  Splitting is now bracket- and quote-aware, per-site params are stripped out of
  the site list, and the modification identifier namespaces are closed to the
  three the spec admits (`MOD`, `UNIMOD`, `CHEMMOD`), so a cvParam can no longer
  pass as a PTM. Regression tests:
  `test_a_neutral_loss_parameter_is_not_claimed_as_a_modification`,
  `test_a_neutral_loss_without_a_modification_yields_no_claim`,
  `test_a_per_site_probability_parameter_keeps_the_modification_and_its_sites`.
- **Param fields were split on bare commas.** mzTab §5.10 quotes any param field
  containing one, so a quoted FDR term name shifted the fields and reported a
  fragment of the name as the threshold. Regression test:
  `test_a_quoted_comma_in_a_parameter_name_does_not_split_the_parameter`.
- **`identified_by` carried the serialised param** (`[MS, MS:1001207, Mascot,]`)
  as its object, which resolves to nothing downstream. The claim now carries the
  engine's name with its PSI-MS accession as the object's ontology term, the
  same way `fdr_controlled_at` already did.
- **`"--"` was treated as an mzTab null marker** and documented as being "per
  the specification". mzTab §5.9 requires `"null"`; `"--"` is not in the format.
  Removed.
- **A foreign CURIE resolved to an EDAM topic.** EDAM lists the identifiers it
  cross-references among its own synonyms (`GO:0006464` and `MOD:00000` both sit
  under Protein modifications), so `_edam.lookup()` answered a slot that already
  named a GO or PSI-MOD term with an EDAM topic — an identity rewritten as a
  subject heading, which is the failure this package's exact-match policy exists
  to prevent. CURIE-shaped text is now refused. Regression test:
  `test_a_foreign_curie_does_not_resolve_to_an_edam_topic`.
- **`tests/fixtures/sample.mztab` paired `MS:1002350` with `protein:global
  FDR`.** PSI-MS `MS:1002350` is *PSM-level global FDR*; protein-level global
  FDR is `MS:1001214`. Corrected, and the test now asserts the accession and the
  scope it travels with name the same thing.
- **`_edam` cited a `scripts/build_index.py` that does not exist.** The EDAM
  index cannot be regenerated from this repository; the docstring and README now
  say so instead of pointing at a missing file.
- **`Phospho` was said to name eleven PSI-MOD terms.** It is the PSI-MS label of
  ten in release 1.038.0.

### Added
- `tests/test_asb_namespace_alignment.py` — the sibling's tripwire, absent here:
  the shapes file hardcodes the `asb:` base, so a base move that updates indicium
  but misses the shapes would fail open with `conforms=True` against zero
  constraints.
- `test_every_edam_entry_points_at_an_edam_topic` and a strengthened
  `test_edam_index_records_the_roots_it_was_cut_from`, which asserted only that
  the roots list was non-empty.

## [0.2.0] — 2026-08-22

Brings the package into line with the `indicium-adapters-metabolomics` sibling:
shared namespace module, PSI-format claim projections, SHACL shapes, and a
domain-identity enrichment layer beyond EDAM.

### Added
- **`_namespaces.PROTEOMICS_PREFIXES`** — the prefix map moves out of the
  adapter class into one file, with the owning authority named against each
  prefix. `PXD` (ProteomeXchange), `PRIDE` (EMBL-EBI), `MSV` (MassIVE) and
  `PASS` (PeptideAtlas) are added; `MS`, `MOD`, `PR`, `GO`, `OBI`,
  `NCBITaxon`, `UBERON`, `uniprot` and `edam` carry over unchanged.
- **`uniprot_curie()`** — resolves a protein accession to a `uniprot:` CURIE
  using UniProtKB's own published accession grammar. Accepts bare accessions,
  isoform suffixes, `UniProtKB:`-prefixed CURIEs and the UniProtKB FASTA header
  form (`sp|P02768|ALBU_HUMAN`).
- **`psimod_curie()`** and a bundled PSI-MOD index (5,135 labels, PSI-MOD
  release 1.038.0) generated by `data/build_psimod_index.py` from the HUPO-PSI
  `PSI-MOD.obo`. Labels claimed by more than one MOD term are absent from the
  index by construction; a 29-entry alias layer
  (`data/_ptm_aliases.json`) adds process nouns ("phosphorylation"), each
  pointing at a PSI-MOD *name* resolved through the same index.
- **`mztab.parse_mztab_to_claims()`** — projects a proteomics mzTab 1.0 file's
  MTD, PRT, PEP and PSM sections into ASB claim dicts: `fdr_controlled_at`,
  `identifies_protein`, `identified_by`, `searched_against`,
  `identifies_peptide`, `matched_to_spectrum`, `carries_modification`
  (site positions in evidence) and `has_abundance`.
- **`mzid.parse_mzid_to_claims()`** — projects mzIdentML 1.1/1.2 search results.
  Only accessions reached through a non-decoy `PeptideEvidence` are reported
  identified; only threshold-passing `SpectrumIdentificationItem`s become
  spectrum matches.
- **`shacl_shapes()`** — the adapter is now a `SHACLProvider`, shipping
  `asb:ProteomicsClaimCurieShape` for CURIE-prefix validation. A test asserts
  the shape's prefix alternation and `PROTEOMICS_PREFIXES` stay in step.
- Four qualifiers required by the projections: `identifies_protein`,
  `identifies_peptide`, `matched_to_spectrum`, `has_abundance`.

### Changed
- `enrich_claim()` now walks a three-step resolution ladder — UniProtKB, then
  PSI-MOD, then EDAM — and reports UniProt hits as `semapv:CompositeMatching`
  rather than `semapv:LexicalMatching`, since an accession is matched against a
  grammar and not against a label.
- Depends on `rdflib>=7.0` for the SHACL shapes.

### Fixed
- `enrich_claim()` left a stale `ontology_terms_unmatched` entry on the returned
  claim when a slot recorded as unmatched by an earlier pass resolved on this
  one, so the claim contradicted itself. Regression test:
  `test_a_resolved_slot_is_cleared_from_a_stale_unmatched_entry`.

## [0.1.0] — 2026-08-21

Initial release: `ProteomicsAdapter` with the classification vocabulary
(`primary_domain`, `subdomains`, `techniques`), curated claim qualifiers, and
exact-match concept enrichment against a vendored EDAM label index.
